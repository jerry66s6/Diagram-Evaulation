What changed in the SVG evaluator?

The same original partial edits are scored with v1 and v2 below. V2 checks explicit sequence pairs, spatial relations, and group membership. Each dimension uses its lowest measurable required criterion; other passing checks cannot compensate for that failure. The severe column uses a different, stronger edit.

How scores are calculated

  1. All images share a frozen description-derived component inventory and explicitly transcribed spatial requirements.
  2. The SVG judge checks source geometry. GPT receives the rendered image and frozen expectations, with no target-dimension or degradation-level labels. One API call judges all five dimensions of an image.
  3. Individual criteria are passing opportunities / total opportunities. Presence is drawn / decided components; Details is correctly labeled / drawn components. Uncertain components are excluded.
  4. A dimension is the minimum of its available criterion scores. Zero opportunities is N/A and is excluded.
  5. Combined scores take the median between judges for each matching criterion, then the minimum across the dimension’s criteria. With two judges, the median is their average. A missing GPT result means Combined is pending.
  6. Overall weights remain: Layout 10%, Connectivity 40%, Presence 20%, Details 10%, Legibility 20%. Weights are renormalized if a dimension is N/A.
